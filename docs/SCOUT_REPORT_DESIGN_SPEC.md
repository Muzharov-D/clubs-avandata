# Scout Report — Design Spec

> Извлечено из референса **FC_MOSSMAN Analytics** (player scouting one-pager,
> Luka Vušković / Hamburger SV). Цель: переиспользуемый визуальный язык
> «скаут-репорта игрока» поверх существующей дизайн-системы Clubs Avandata.
> Это спецификация, не production-код. Снимки токенов даны как контракт.

---

## 0. Что это и когда применять

Плотный аналитический one-pager на одного игрока: перцентили по амплуа,
поведенческие наклонности (tendencies), динамика ценности во времени и
позиционирование среди peers. Регистр — **product / data-viz** (дизайн служит
данным), не маркетинг. Холст рассчитан на экспорт в PNG/PDF (шеринг скаутами),
поэтому фиксированная сетка-полотно важнее «резинового» поведения.

Применять для: карточка-репорт игрока, экспортируемый отчёт, сравнение с
peer-группой. НЕ применять как общий стиль приложения — это «парадный» слой.

---

## 1. Цветовая стратегия

Референс — **committed single-accent** на near-black холсте: один зелёный несёт
все «наши»/важные акценты, нейтральный off-white — peer-объекты, белый —
benchmark-линии. Это совпадает с философией Clubs Avandata (тёмная аналитика +
один бренд-акцент), поэтому **новых базовых цветов почти не нужно** — мапим на
существующие токены.

### 1.1 Маппинг на существующие токены

| Роль в репорте | Референс (≈) | Токен Clubs Avandata | Примечание |
|---|---|---|---|
| Холст | `#0d0d0d` | `--bg-page` `#0a0c10` | уже глубже — оставляем |
| Поверхность панели | — | `--bg-surface` `#141821` | панели репорта |
| Главный акцент («наш игрок», заливки) | `#5aa83c` олив-грин | `--brand-accent` `#22c55e` | акцент-зелёный уже есть |
| Текст-данные | `#f0f0f0` | `--text` `#f3f6fc` | |
| Подписи осей/тиков | серый | `--text-muted-strong` `#b4c0d2` | WCAG-safe на surface |
| Peer-объекты (точки, чужие линии) | off-white `#efe9d8` | **новый** `--report-peer` | см. 1.2 |
| Benchmark-линии (Elite/Avg/Poor) | белый/серые | `--text-muted` / `--border-strong` | градации серого |
| Рукописные аннотации | зелёный | `--brand-accent` | только акцент, не текст-цвет |

### 1.2 Новые токены (добавить в `:root`, scope — репорт)

```css
/* Scout report — слой поверх базовой темы */
--report-accent:      var(--brand-accent);            /* «наш игрок», заливки радара */
--report-accent-soft: color-mix(in srgb, var(--brand-accent) 22%, transparent);
--report-peer:        #e7e0cf;   /* off-white: peer-точки, чужие линии */
--report-peer-dim:    color-mix(in srgb, var(--report-peer) 55%, transparent);
--report-ink:         var(--text);
--report-grid:        rgba(255,255,255,0.06);         /* сетка чартов */
--report-band-elite:  rgba(255,255,255,0.16);         /* benchmark-полосы */
--report-band-avg:    rgba(255,255,255,0.10);
--report-band-poor:   rgba(255,255,255,0.05);
```

> **Важно (identity-preserve + white-label):** акцент репорта = `--brand-accent`,
> поэтому при смене tenant-бренда (`applyTheme`) репорт автоматически перекрасится
> в цвет клуба. НЕ хардкодить зелёный — это сломает мульти-тенантность (см.
> CLAUDE.md «Цвета — ТОЛЬКО через CSS vars»).

### 1.3 Контраст (обязательно)

- Данные/числа поверх `--bg-page`/`--bg-surface`: `--text` (≈13:1) — ок.
- Подписи осей: `--text-muted-strong` (5.4:1), не `--text-faint` для мелкого.
- `--report-peer` `#e7e0cf` на `--bg-page` ≈ 13:1 — peer-точки читаемы.
- Зелёный акцент как **заливка** — ок; зелёный как **текст подписи** на тёмном
  ≥ 4.5:1 проверить (`#22c55e` на `#0a0c10` ≈ 7:1 — проходит, но крупный/bold).

## 2. Типографика

Референс держит **3 семейства** (потолок impeccable): маркерный дисплей для
имени-заголовка, рукописный для аннотаций, чистый sans для меток/чисел.
У вас уже есть Space Grotesk + Inter — добавляем **только рукописный** слой.

| Роль | Референс | Рекомендация для Clubs Avandata |
|---|---|---|
| Имя игрока (H1) | толстый маркер-гротеск | `--font-display` (Space Grotesk 700) — **не** тащить комикс-шрифт в продукт |
| Заголовки панелей | bold sans | `--font-display` 600, ~16–18px |
| Рукописные аннотации | handwritten (Caveat-подобный) | **новый** `--font-annot`: `'Caveat'` или `'Kalam'`, 600 |
| Метки осей / числа | sans | `--font` (Inter) / числа — Space Grotesk tabular |

```css
--font-annot: 'Caveat', 'Comic Neue', cursive;  /* только аннотации */
```

Правила:
- Рукописный шрифт **только** в слое аннотаций (стрелки-подписи). В таблицах,
  осях, числах — запрещён (нечитаемо на мелком).
- Числа в чартах/тиках — `font-variant-numeric: tabular-nums` (Space Grotesk),
  чтобы цифры не «прыгали».
- Имя игрока: `text-wrap: balance`, letter-spacing ≥ -0.04em, ceiling ≤ 6rem.
- Без ALL CAPS в подписях длиннее 4 слов (заголовки панелей — Title Case).

## 3. Система аннотаций (подпись-стрелка) — сигнатурный приём

Самая узнаваемая черта референса: **рукописные зелёные подписи + пунктирные
изогнутые стрелки**, указывающие на конкретные точки данных
(«utterly dominant in the air for his age» → стрелка к Aerial Duel %).

### Спецификация
- **Текст:** `--font-annot`, цвет `--report-accent`, 14–16px, 2–3 строки макс.
- **Стрелка:** пунктир (`stroke-dasharray: 6 5`), `--report-accent`, толщина 2px,
  изогнутая (quadratic/cubic путь), наконечник — маленький треугольник.
- **Якорь:** стрелка начинается у текста, кончается у целевой точки/сектора.
- **Тон копирайта:** конкретный инсайт, не маркетинг. «lower pass accuracy
  relative to age peers» — хорошо. Без бузвордов, без em-dash.

### Реализация (направление, не код)
- SVG-оверлей поверх чарта (`position:absolute; inset:0; pointer-events:none`),
  пути в координатах контейнера. Либо аннотации чарт-библиотеки.
- Для экспорта в PNG путь должен быть в том же SVG, что и чарт.

### Доступность и устойчивость (критично)
- Аннотации **декоративны**: `aria-hidden="true"`. Инсайт обязан дублироваться
  в доступном виде (подпись/таблица), иначе скринридер теряет смысл.
- **Данные должны читаться без аннотаций.** Аннотация — поверх уже валидного
  чарта (правило impeccable: reveal/overlay усиливает видимый дефолт, не заменяет).
- На узких экранах аннотации скрываются или уходят в список «Выводы» под чартом
  (см. §6) — изогнутые стрелки на мобиле не работают.
- `@media (prefers-reduced-motion)` — если стрелки «рисуются», дать статичный вид.

## 4. Чарт-паттерны

Четыре панели. Для каждого — модель данных, кодировка, цвет, состояния.

### 4.1 Percentile Radar (CB Radar Chart)
- **Назначение:** профиль игрока по N метрикам амплуа в **перцентилях** (0–100%)
  относительно peer-группы (u21, T5-лиги, 900+ мин).
- **Данные:** `{ axis: string, percentile: 0..100 }[]` (8–14 осей). Перцентиль,
  не сырое значение — иначе оси несопоставимы.
- **Кодировка:** одна заливка `--report-accent-soft`, контур `--report-accent` 2px.
  Радиальная сетка `--report-grid`, тики 0/20/40/60/80/100.
- **Подпись осей:** сокращения (`Aerial Duel %`, `Int`, `Prg Runs`), `--font` 12px.
- **Состояния:** <3 осей с данными → не строить радар (вырожденный); показать bars.
- **Привязка:** группируется по амплуа (CB/FB/CM/FW) — нужен набор осей на роль.

### 4.2 Diverging Tendencies Bars (Player Tendencies)
- **Назначение:** поведенческие наклонности как **z-score** (отклонение от среднего
  peer-группы), диверг-бары влево/вправо от 0.
- **Данные:** `{ metric, z: number }[]` (напр. Fwd Pass/Pass, PrgR/Pass Rec,
  Ground/Air Duels, Shield/Sword). Это **соотношения/склонности**, не объёмы —
  это и есть «не раздуто высоким touch volume».
- **Кодировка:** бар вправо (положит.) = `--report-accent`; влево/нейтраль =
  `--report-peer`. Ось 0 — вертикаль `--border-strong`. Сетка по X (−2..5).
- **Метки:** слева названия, шкала снизу. Без числа на каждом баре (шум) —
  только ось.

### 4.3 Rolling Value (Rolling 20 Match Recruitment Value)
- **Назначение:** скользящая (rolling 20 матчей) композитная «ценность» игрока во
  времени vs benchmark-полосы Elite/Avg/Poor.
- **Данные:** серия `{ matchIndex, value }[]` + горизонт. уровни benchmark.
- **Кодировка:** линия игрока — белая/`--report-ink`, **прогноз/тренд** —
  `--report-accent` пунктир (стрелка-тренд). Полосы Elite/Avg/Poor —
  `--report-band-*` (градации). Легенда сверху.
- **Нюанс:** «continuous upward trajectory» = пунктирная трендовая стрелка от
  старта к концу (тот же приём, что аннотации §3, но как данные).
- **Состояния:** <N матчей → «недостаточно данных для rolling» (не рисовать шум).

### 4.4 Peer Scatter (Prg Runs vs Aerial Duels Won)
- **Назначение:** позиционировать игрока в 2D (две метрики p90) среди peers.
- **Данные:** `{ name, x, y, isTarget?, isLabeled? }[]`.
- **Кодировка:** peers — `--report-peer` точки; **наш игрок** — `--report-accent`
  точка крупнее + подпись `--font-annot`. 2–3 именованных ориентира (peer-звёзды)
  подписать `--font` (`J. Martin`, `D. Huijsen`).
- **Оси:** подписаны, тики `--text-muted-strong`, сетка `--report-grid`.
- **Анти-перегруз:** подписывать только target + якорные peers, остальные — точки.

### Общие правила чартов
- Сетка тусклая (`--report-grid`), оси читаемые, данные ярче сетки.
- Tabular-nums на всех числах. Единицы (`%`, `p90`) в подписи оси, не на каждом тике.
- Пустое состояние у каждого: «нет данных за период / мало матчей» (как уже
  сделано в блоке «Командные показатели», см. `ClubDashboard`).
- Экспорт: чарты как SVG (резкость в PNG/PDF), не canvas-растр.

## 5. Заголовочная зона (header band)

- Слева: имя (`--font-display` 700), под ним мета-строка — `CB · 18 · Hamburger SV · 🇭🇷`
  (`--text-muted-strong`), и источник данных мелким (`Wyscout 11.13.25: u21 T5 CBs, 900+ min`).
- Справа: лого аналитика/клуба (`--brand-*`), выравнивание по верхней линии.
- Разделение — воздух, без рамок-стрипов (бан impeccable на side-stripe borders).

---

## 6. Лейаут и адаптив

- **Десктоп/экспорт:** 2×2 сетка панелей (`grid-template-columns: 1fr 1fr`),
  фиксированная ширина-полотно (напр. 1600px) для стабильного PNG.
- **Планшет:** 2 колонки → можно оставить, ужать паддинги.
- **Мобайл (<720px):** 1 колонка, панели стопкой. Изогнутые аннотации-стрелки
  **скрыть**, их инсайты собрать в блок **«Ключевые выводы»** (буллеты
  `--font` обычным текстом) под каждым чартом — смысл сохраняется без SVG-стрелок.
- Панели — `--bg-surface`, `--radius-lg`, `--shadow`. **Без вложенных карточек.**

## 7. Привязка к Clubs Avandata

- **Куда:** новая страница/таб репорта рядом с `PlayerDetail.jsx` (профиль игрока
  уже есть), либо экспорт-режим оттуда. Радар амплуа можно частично переиспользовать
  как один блок в `PlayerDetail` (это был средний по объёму вариант — здесь только спек).
- **Токены:** переиспользуем `--bg-*`, `--text-*`, `--brand-accent`, `--radius-*`,
  `--shadow*`. Добавляем `--report-*` (§1.2) и `--font-annot` (§2).
- **Шрифт аннотаций:** подключить Caveat/Kalam через тот же механизм, что Inter/
  Space Grotesk (Google Fonts / self-host). Один новый вес.
- **Чарт-библиотека:** определить отдельно (radar/scatter/diverging — кастомный SVG
  или recharts/visx; rolling — линия с band-областями). Решение по библиотеке —
  открытый вопрос (см. §9), от него зависит реализация аннотаций.
- **Данные/перцентили:** для радара и scatter нужна **peer-группа и перцентили**
  (u21, лига, минут-фильтр). Это backend-агрегат поверх `players/season` —
  крупная работа, отдельно от этого спека.

## 8. Анти-слоп и ловушки

- НЕ тащить комикс/маркер-шрифт дальше имени и аннотаций — продукт ≠ мем.
- НЕ хардкодить зелёный (ломает white-label) — только `--brand-accent`/`--report-*`.
- НЕ перегружать scatter подписями — target + 2–3 якоря.
- НЕ строить вырожденные чарты на 1–2 точках — показывать пустое состояние.
- Аннотации — декор поверх валидных данных, не носитель смысла (a11y, §3).
- Без side-stripe рамок, без gradient-text, без glassmorphism-панелей.
- Числа — tabular-nums, перцентили (не сырьё) на радаре.

## 9. Открытые вопросы

1. **Чарт-библиотека**: кастомный SVG (полный контроль аннотаций/экспорта) vs
   recharts/visx (быстрее, но аннотации-стрелки сложнее). → влияет на §3/§4.
2. **Источник перцентилей**: есть ли peer-данные (u21/лига/минуты) в БД, или
   перцентиль считается только внутри тенанта? → определяет ценность радара/scatter.
3. **Экспорт**: нужен ли PNG/PDF-экспорт (тогда фикс-полотно + SVG обязательны)
   или только интерактив в вебе?
4. **Рукописный шрифт**: Caveat (легче) vs Kalam (плотнее) — согласовать тон.
