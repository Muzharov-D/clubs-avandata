# Практикум: прототипирование проектов с Claude Cowork / Code
_2026-06-04 · 7–10 часов · пошагово, руками_

## Для кого и итог
Практикум для сотрудников, которые после первой встречи хотят **сами собирать
прототипы** с помощью Claude. К концу каждый участник проходит путь
**идея → бриф → работающий прототип → демо** и делает это руками, а не смотрит.

**Результат на выходе:** у каждого — свой мини-прототип (экран/фича/утилита),
запущенный локально, и понимание повторяемого процесса.

## Принцип: разноуровневость
По итогам анкеты ЗУН делим на треки и держим их параллельно:
- **A — старт:** ведём за руку, общий проект-«рельса», каждый шаг показываем.
- **B — рост:** свой проект, минимум подсказок, помощь по запросу.
- **C — про:** свой проект + доп. вызовы (скилы, субагенты, автоматизация).

Один материал, разная глубина: базовая инструкция + «➕ для трека C» врезки.

## Перед практикумом (асинхронно, ~30 мин)
- Установить Claude Code / получить доступ к Cowork, проверить вход.
- Поставить редактор (VS Code), git, Node.js (или нужный рантайм).
- Завести пустую папку под проект, проверить, что `claude` запускается.
- Придумать черновую идею прототипа (можно из вопроса 8 анкеты).

> Сетап выносим из часов практикума — иначе он съест первый модуль. Проверку
> готовности делаем чек-листом заранее.

## Программа (8.5 ч ядро + буфер = 7–10 ч)

### Модуль 0. Ориентация (0.5 ч)
- Что такое Claude Code и Cowork, чем отличаются, когда что.
- Интерфейс: чат, файлы, режимы (план/авто), как Claude читает и правит проект.
- Правила безопасной работы: подтверждения, git как «кнопка отмены».
- **Практика:** запустить Claude в своей папке, задать первый вопрос про проект.

### Модуль 1. Язык общения с Claude (1 ч)
- Как ставить задачу: контекст → цель → ограничения → формат.
- Дать контекст файлами и примерами; почему «больше контекста» ≠ «лучше».
- Итерация через диалог: уточнять, а не переписывать с нуля.
- **Практика:** на учебной задаче довести ответ до рабочего за 3–4 итерации.
- ➕ **C:** кастомные инструкции / `CLAUDE.md`, режим плана для крупной задачи.

### Модуль 2. От идеи к брифу (1 ч)
- Почему прототип начинается с брифа, а не с кода.
- Формат: **для кого и зачем · scope · критерии · открытые вопросы**.
- **Практика:** каждый формулирует бриф своего прототипа (трек A — общий бриф).
  Можно прямо через скил «бриф к прототипу».
- **Чекпоинт:** у всех есть бриф на один экран. Без брифа дальше не идём.

### Модуль 3. Первый прототип (1.5 ч)
- Каркас проекта: попросить Claude развернуть структуру под бриф.
- Запуск: поднять локально, открыть в браузере, увидеть «живое».
- Цикл «попросил → запустил → посмотрел → поправил».
- **Практика:** получить первый видимый экран прототипа.
- ➕ **C:** выбор стека осознанно, разбиение на модули, заготовка под тесты.

### Модуль 4. Итеративная разработка по шагам (1.5 ч)
- Добавляем фичи по одной; маленькие шаги вместо «сделай всё».
- git: коммит после каждого рабочего шага, откат при поломке.
- Когда Claude ошибается: как читать ошибку и просить точечный фикс.
- **Практика:** 3–4 фичи к прототипу, каждая — отдельный коммит.
- ➕ **C:** ветки, осмысленные сообщения коммитов, фикс по логам/ошибкам сборки.

### Модуль 5. Скилы и помощники (1 ч)
- Что такое skills и субагенты, зачем выносить повторяемое.
- **Практика:** собрать маленький свой скил (например, генератор чего-то под
  свою рутину) и вызвать его.
- ➕ **C:** субагенты под подзадачи, параллельный запуск.
- _(Трек A — это знакомство «что бывает», без обязательной сборки.)_

### Модуль 6. Контроль качества (1 ч)
- Проверка глазами + ревью кода силами Claude; что значит «готово».
- Базовые тесты и быстрый прогон; не доверять слепо сгенерированному.
- Типичные грабли: «выглядит правильно, но не работает».
- **Практика:** прогнать ревью своего прототипа, починить найденное.

### Модуль 7. Демо и разбор (1 ч)
- Каждый показывает прототип за 2–3 минуты: бриф → что вышло → что дальше.
- Групповой разбор: что сработало, где застряли, как ускориться.
- Личный план следующего шага.

## Тайминг — варианты упаковки
| Формат | Как разбить |
|---|---|
| **7 ч** (плотно) | Урезать M5 до обзора, M7 до 0.5 ч, практику чуть короче |
| **8.5 ч** (база) | Программа как есть |
| **10 ч** (с запасом) | +буфер на отставание, +доп. практика в M3/M4, длиннее демо |

Рекомендую **2 встречи по ~4 часа** (или 3 по ~3 ч) с домашним мини-заданием
между ними, а не один марафон — внимание садится.

## Что подготовить ведущему
- Учебный «рельса»-проект для трека A (чтобы новички не застряли на старте).
- Чек-лист готовности окружения (рассылается заранее).
- 2–3 примера брифов и готовых прототипов как образцы.
- Шпаргалка по типичным ошибкам и командам git (откат, коммит, ветка).
- Заготовки задач разной сложности под треки A/B/C.

## Критерии успеха практикума
- ≥80% участников вышли с **запущенным** прототипом.
- Каждый может объяснить цикл «бриф → шаг → проверка → коммит».
- Участники треков A и C **не скучали** — материал лёг по уровню (проверяем
  короткой анкетой-обраткой после, как в `anketa-zun-ai.md`).

- Темы прототипов свободные или из рабочих задач компании?
