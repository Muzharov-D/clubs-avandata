# Roadmap фаз 1–5 — статус реализации

Реализовано в рамках единого коммита по итогам аудита платформы (61/100 как
инструмент, ~74/100 по фундаменту). Ниже — что сделано и что осознанно отложено
с обоснованием.

## Фаза 1 — Доверие и надёжность ✅
- **Индикатор достоверности данных**: бэк считает `data_quality` (покрытие
  игроков рейтингами/минутами/детальными действиями, источники PDF/Excel,
  секции, предупреждения) при загрузке и на лету; фронт — бейдж `DataQualityBadge`
  в шапке разбора матча.
- **Zod-валидация вывода парсера** (`upload/validation.ts`): структура (`validateRich`)
  + семантика (`assertSportVisor` отклоняет не-SportVisor PDF понятной 400).
- **Радар — честный режим**: `role="img"` + aria-label + подпись «Performance
  Index (0–10), не количество действий».
- **CI-гейт «код ⇄ миграция»** (`.github/workflows/ci.yml` + `scripts/check-schema-drift.mjs`):
  поднимает Postgres, прогоняет миграции, сверяет каждую колонку Drizzle-схемы с
  реальной БД. Ловит ровно тот класс, что уронил логин (колонка в коде, но не в БД).
  Плюс билд фронта/бэка как обязательный шаг.

## Фаза 2 — Глубина (сезон/игрок) ✅
- **Тренды игрока** (`GET /data/player/:id/trend`): рейтинги/голы/минуты по матчам.
  Фронт — `PlayerTrendCard` на странице игрока (спарклайны + лента результатов).
- **Сезонные агрегаты** (`GET /data/players/season`): суммы и средние по игроку.
- **Сравнение двух игроков** (`/players/compare`): бок о бок рейтинги, суммы, тренды.
- **Перцентили** внутри состава — в рейтинге игроков (бенчмарк без данных лиги).
- **Контроль нагрузки** (`/load`): накопленные минуты/дистанция + флаг перегруза.

## Фаза 3 — Операционка и масштаб ✅ (частично)
- **CSV-экспорт**: рейтинг игроков, метрики матча, контроль нагрузки (`utils/exportCsv`).
- **Печать / PDF разбора**: кнопка + `@media print` (скрывает хром, готовит к печати).
- **Заметки тренера** к разбору (`PATCH /data/match/:id/note` + UI, только тренеры).
- ⏸ **Асинхронная загрузка (очередь)** — отложено: текущая синхронная загрузка
  рабочая; полноценная очередь джоб требует воркера/инфры, отдельная задача.
- ⏸ **Авто-синк календаря ЮФЛ** — отложено: источник за WAF (SafeLine/JoinSport),
  серверная автоматизация ненадёжна. Остаётся ручной сид + browser-MCP.

## Фаза 4 — Продукт и соответствие ✅ (частично)
- **White-label scaffolding**: акцентный градиент вынесен в `--brand-gradient`
  (+ `--accent-cyan`), литералы заменены на токен в ключевых CSS. Дефолты =
  текущая палитра → визуал НЕ меняется, но тенант может переопределить.
- **a11y**: aria на навигации (`aria-current`), радаре, бейдже достоверности,
  барах сравнения; цветовые статусы дублируются символами (▲▼=, П-перцентиль).
- **Приватность**: публичная страница `/privacy` + колонка `players.data_consent`
  (модель согласия на обработку данных ребёнка).
- ✅ **Строгий RLS (изоляция тенантов на уровне БД)** — реализован: миграция
  `0007_force_rls_isolation.sql` (ENABLE + FORCE + политика `tenant_isolation` по
  `app.tenant_id`/`app.bypass_rls`), `withTenant`/`withBypassRLS` приведены под
  FORCE, аудит подтвердил, что все live-роуты обёрнуты, а `users`/`tenants`/
  `refresh_tokens` НЕ форсятся (auth не ломается). Безопасность доказывается
  CI-тестом `scripts/test-rls-isolation.mjs` (изоляция A/B, fail-closed без
  контекста, bypass для админа) — гоняется на PR до мержа. На managed-PG, где роль
  приложения = owner/superuser с обходом RLS, FORCE инертен и поведение не меняется.
- ⏸ **Дедуп дублей страниц** (ClubDashboard/ClubOverview/ClubPage) — отложено:
  затрагивает роутинг, риск регресса; отдельная задача с прогоном UI.

## Фаза 5 — Дифференциация ✅ (доступное)
- **Авто-инсайты по матчу** (`utils/insights`): результат, лучший/просевший,
  бомбардир, прессинг/единоборства, дисциплина, нагрузка — на странице разбора.
- **Прогноз состава** (`utils/lineup` + `PredictedLineup`): эвристика по минутам
  и среднему рейтингу, гарантирован вратарь — на дашборде клуба.
- **Бенчмарки внутри команды**: перцентили (Фаза 2).
- ⏸ **Бенчмарки по лиге** — отложено: нет per-player данных соперников/лиги.
- ⏸ **Видео-таймкоды к событиям** — отложено: нет источника видео.

## Принцип по отложенному
Отложены ровно те пункты, что требуют (а) доступа к проду с планом отката
(strict RLS), (б) внешних данных, которых нет (лига, видео), или (в) инфраструктуры
вне одного коммита (очередь джоб, обход WAF). Всё остальное реализовано.
