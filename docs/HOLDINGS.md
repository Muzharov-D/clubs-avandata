# Холдинги в кабинете федерации

Холдинг — группа школ одного бренда, которую федерация (и сам клуб) хочет видеть как одну
вертикаль: все возраста, обе лиги, каждая команда целиком. Первый холдинг — **«Динамо
Санкт-Петербург»**: ФК Динамо (Высшая лига) + Царское Село-Динамо (Первая лига), U14–U18.

Адрес: `/federation/holdings/:slug` (роль `federation_admin`). Пункт в сайдбаре «Холдинги»
и ссылка «Страница холдинга» в карточке клуба появляются автоматически из конфига.

## Где что

| Слой | Файл | Что делает |
|---|---|---|
| конфиг + сборка | `backend/src/federation/holdings.ts` | `HOLDINGS` (slug, бренд, участники, годы), `holdingProfile()` — профиль за сезон, `warmHoldings()` — прогрев |
| маршруты | `backend/src/federation/routes.ts` | `GET /api/v1/federation/av/holdings` (список), `GET …/holdings/:slug` (профиль) |
| прогрев | `backend/src/server.ts`, `backend/src/cron/runner.ts` | через 15 с после старта и каждые 8 мин (`holdingsWarm`, при `START_CRONS=true`) |
| страница | `frontend/src/routes/federation/HoldingView.tsx` + `holding.css` | шапка в цветах клуба, KPI, матрица «возраст × школа», разбор команды, лучшие игроки, сборная |
| навигация | `frontend/src/routes/federation/FederationLayout.tsx`, `ClubCard.tsx` | пункты «Холдинги», ссылка из карточки клуба |
| тесты | `backend/src/federation/holdings.test.ts` | сшивка имён, форма, линии амплуа, сборная |

## Как добавить холдинг

В `HOLDINGS` добавить запись:

```ts
{
  slug: 'zenit-spb',                       // адрес /federation/holdings/zenit-spb
  name: 'Зенит Санкт-Петербург', short: 'Зенит СПб', region: 'Первенство Санкт-Петербурга',
  brand: { primary: '#0b3f8f', bright: '#5d95ff', soft: 'rgba(11,63,143,0.30)', onPrimary: '#fff' },
  members: [{ key: normTeam('ФК Зенит'), label: 'ФК Зенит' }, { key: normTeam('СШОР Зенит'), label: 'СШОР Зенит' }],
  years: [2009, 2010, 2011, 2012, 2013],
}
```

Участники сшиваются **по имени** через `normTeam` (у AvanData и ФФСПб разные id): «ФК Динамо
2011» и «ФК Динамо-СПб» дают один ключ `динамо`, а «СШ Петроградского района - Динамо» —
другой. Перед добавлением проверьте ключи тестом (`holdings.test.ts`) — это дешевле, чем
искать «пропавшую» команду на проде. Цвета берите из логотипа (см. `brand`), логотипы
приходят из данных (AvanData/ФФСПб) — хранить их в репо не нужно.

## Откуда данные и что с ними бывает

- **Таблицы** — `regionStandings(year)`: официальный API ФФСПб (через Vercel-прокси
  `/ffspb-api`), при сбое — зеркало AvanData c пометкой `degraded` (на странице — жёлтый бейдж;
  зеркало иногда теряет команду в дивизионе).
- **Рейтинг команды и место по рейтингу** — `getTeamsRatings/{tournamentId}` по когорте, ранг
  считается внутри дивизиона без среза «топ-10».
- **Состав, средний класс, «в топ-30 лиги»** — `regionPlayers(year)` (оба дивизиона),
  игроки школы по `normTeam(clubName(team))`; рейтинг с ≥2 разобранных матчей; «топ-30» — 30
  сильнейших своего возраста и дивизиона (методика `talentConcentration`).
- **Матчи** — `getListMatches` по всем турам дивизиона (+2 тура вперёд для календаря).
  Сыгран = `status === 'ready'` **и есть голы**: в зеркале «ready 0:0» — это незаполненный
  протокол (как в `regionResults`). Баланс В-Н-П в сводке берётся из таблиц, а не из матчей.

Сборка тяжёлая (десятки запросов к внешним API, ФФСПб-таблицы с ретраями — до минут на
холодном старте), поэтому профиль живёт в SWR-кэше: протухший отдаётся сразу, свежий
собирается фоном; плюс прогрев на старте и по расписанию. Пользователь видит холодный старт
только если сервер поднялся меньше минуты назад.

## Известные ограничения

- Официальные таблицы ФФСПб: `stat.ffspb.org` теперь редиректит на `ffspb.org`, а
  `/api/standings/*` там отвечает по 1–2 минуты — сборка чаще падает на зеркало. Правило
  прокси в `vercel.json` уже смотрит на `ffspb.org/api`; если ФФСПб ускорится, официальные
  таблицы вернутся сами.
- Публичной (без входа) версии страницы пока нет — при необходимости делается по образцу
  `/league/video/:id` (ссылка по токену).
