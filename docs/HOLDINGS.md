# Холдинги в кабинете федерации

Холдинг — группа школ одного бренда, которую федерация (и сам клуб) хочет видеть как одну
вертикаль: все возраста, обе лиги, каждая команда целиком. Первый холдинг — **«Динамо
Санкт-Петербург»**: ФК Динамо (Высшая лига) + Царское Село-Динамо (Первая лига), U14–U18.

Адрес: `/federation/holdings/:slug` (роль `federation_admin`). Пункт в сайдбаре «Холдинги»
и ссылка «Страница холдинга» в карточке клуба появляются автоматически из конфига.

## Где что

| Слой | Файл | Что делает |
|---|---|---|
| конфиг + сборка | `backend/src/federation/holdings.ts` | `HOLDINGS` (slug, бренд, участники, годы), `holdingProfile()` — профиль за сезон, `warmHoldings()` — прогрев |
| маршруты | `backend/src/federation/routes.ts` | `GET /api/v1/federation/av/holdings` (список), `GET …/holdings/:slug` (профиль) |
| прогрев | `backend/src/server.ts`, `backend/src/cron/runner.ts` | через 15 с после старта и каждые 8 мин (`holdingsWarm`, при `START_CRONS=true`) |
| страница | `frontend/src/routes/federation/HoldingView.tsx` + `holding.css` | шапка в цветах клуба, KPI, матрица «возраст × школа», разбор команды, лучшие игроки, сборная |
| навигация | `frontend/src/routes/federation/FederationLayout.tsx`, `ClubCard.tsx` | пункты «Холдинги», ссылка из карточки клуба |
| тесты | `backend/src/federation/holdings.test.ts` | сшивка имён, форма, линии амплуа, сборная |

## Как добавить холдинг

В `HOLDINGS` добавить запись:

```ts
{
  slug: 'zenit-spb',                       // адрес /federation/holdings/zenit-spb
  name: 'Зенит Санкт-Петербург', short: 'Зенит СПб', region: 'Первенство Санкт-Петербурга',
  brand: { primary: '#0b3f8f', bright: '#5d95ff', soft: 'rgba(11,63,143,0.30)', onPrimary: '#fff' },
  members: [{ key: normTeam('ФК Зенит'), label: 'ФК Зенит' }, { key: normTeam('СШОР Зенит'), label: 'СШОР Зенит' }],
  years: [2009, 2010, 2011, 2012, 2013],
}
```

Участники сшиваются **по имени** через `normTeam` (у AvanData и ФФСПб разные id): «ФК Динамо
2011» и «ФК Динамо-СПб» дают один ключ `динамо`, а «СШ Петроградского района - Динамо» —
другой. Перед добавлением проверьте ключи тестом (`holdings.test.ts`) — это дешевле, чем
искать «пропавшую» команду на проде. Цвета берите из логотипа (см. `brand`), логотипы
приходят из данных (AvanData/ФФСПб) — хранить их в репо не нужно.

## Откуда данные и что с ними бывает

- **Результаты и таблицы** — живые протоколы ФФСПб (`backend/src/federation/ffspbLive.ts`):
  список матчей турнира `/api/matches?tournament_id=…`. Поведение ФФСПб: первый запрос к
  турниру «прогревает» его 1–3 минуты (ответ висит или 502), после прогрева страницы по 100
  матчей отдаются за секунды. Обрыв запроса раньше времени прерывает прогрев, поэтому
  соединение держится ~140 с (чуть меньше лимита прокси Vercel) и повторяется; все
  обращения к ФФСПб идут через одну очередь (параллель друг друга вешает). Полный список
  грузится один раз и хранится в БД (`ffspb_match_cache`, миграция 0024), дальше каждые
  10 минут докачиваются матчи последних трёх недель и сливаются по id. Таблица дивизиона считается из протоколов: очки → личные
  встречи среди равных → разница → забитые; технические поражения — по счёту протокола.
  Источник помечен `ffspb-live`. Если ФФСПб недоступен и кэша нет — запасной путь:
  `regionStandings(year)` (официальная таблица или зеркало AvanData, `degraded`) и матчи AvanData.
- **Карточка матча (разбор)** — открывается, если AvanData знает этот матч: сшивка по
  `ffspbMatchIdInfo.outter` («/api/matches/3845578») → `avId`. Матч без разбора показывается
  как строка протокола без клика.
- **Рейтинг команды и место по рейтингу** — `getTeamsRatings/{tournamentId}` по когорте, ранг
  считается внутри дивизиона без среза «топ-10».
- **Состав, средний класс, «в топ-30 лиги»** — `regionPlayers(year)` (оба дивизиона),
  игроки школы по `normTeam(clubName(team))`; рейтинг с ≥2 разобранных матчей; «топ-30» — 30
  сильнейших своего возраста и дивизиона (методика `talentConcentration`).

Сборка тяжёлая (десятки запросов к внешним API), поэтому профиль живёт в SWR-кэше: протухший
отдаётся сразу, свежий собирается фоном; плюс прогрев на старте и по расписанию
(`holdingsWarm`, каждые 8 минут). На холодном старте эндпоинт отвечает `202 {status:'warming'}`,
страница показывает скелетон и переспрашивает каждые 8 секунд.

## Известные ограничения

- Официальная таблица ФФСПб (`/api/standings`) отвечает по 1–2 минуты — поэтому таблицы
  считаются из протоколов. Порядок при равенстве очков воспроизводит основные правила
  (личные встречи, разница, забитые), но экзотические тай-брейки регламента не учтены.
- Первая загрузка протоколов турнира ждёт прогрева на стороне ФФСПб (1–3 минуты на турнир,
  турниры по очереди) — на холодном старте страница показывает «идёт прогрев» до ~10 минут.
  Дальше — только инкремент, и кэш в БД переживает рестарты.
- Публичной (без входа) версии страницы пока нет — при необходимости делается по образцу
  `/league/video/:id` (ссылка по токену).

## Кабинет руководства холдинга (`/holding`)

Отдельный кабинет для руководства (роль `holding_admin`, миграция 0025): свой вход, своя
оболочка в цветах клуба, никакой навигации федерации. Аккаунт заводится сидом:

```bash
npm run seed:holding-admin -- dinamo@avandata.ru "Динамо Санкт-Петербург" <пароль> dinamo-spb
```

Федерация (`federation_admin`) может открыть тот же кабинет по `/holding?slug=dinamo-spb`.

| Экран | Что отвечает | Код |
|---|---|---|
| Обзор | где мы среди команд региона; что требует решения; вертикаль | `frontend/src/routes/holding/Overview.tsx` |
| Решения | молодёжка (ярусы, 5 мест), Царское Село → ФК Динамо, на возраст старше, селекция без имён, кого теряем, зона риска, линии | `Decisions.tsx` |
| Команда | место/рейтинг против лиги, линии, состав с местом каждого в регионе и дивизионе, 36 показателей команды, таблица, матчи | `TeamPage.tsx` |
| Игроки | реестр всех игроков холдинга с фильтрами и сортировками | `PlayersPage.tsx` |
| Игрок | место в регионе/дивизионе, отклонение от амплуа, тренд, флаги решений, 36 показателей против амплуа в лиге, профиль | `PlayerPage.tsx` |

Бэкенд: `backend/src/holding/routes.ts` (`/api/v1/holding/{me,profile,analytics,players,players/:id,teams/:key/metrics}`),
расчёты — `backend/src/federation/holdingAnalytics.ts` (относительно лиги + решения, пороги —
именованные константы вверху файла) и `holdingMetrics.ts` (события всех команд когорты →
показатели за матч против амплуа/дивизиона; кэш 6 часов, прогрев по когортам фоном).

Правила решений (по умолчанию, см. константы):
- рейтинг «есть» от 2 разобранных матчей; решения по игроку — от 3; «готов в молодёжку» — от 4;
- молодёжка: 2011 г.р. и старше; «готов» — топ-10% региона своего возраста, «присмотреться» — топ-25%;
- Царское Село → ФК Динамо: рейтинг не ниже медианы игроков Высшей лиги своего возраста;
- на возраст старше: не ниже медианы оценённых игроков команды школы на год старше;
- селекция: чужие игроки из команд слабее нашей (или лигой ниже), топ-35% региона, сильнее нашей линии на 10%+, без имён;
- кого теряем: последние 4 матча ниже предыдущих на 25%+ (от 6 матчей) или пропустил 3+ разобранных матча команды;
- линии: средний рейтинг линии отличается от дивизиона на 12%+.

## Ориентир «Менеджер 360» — что взять, что не повторять

Менеджер 360 (manager360.online) — универсальная система управления спортивной организацией:
тренировки, медицина, скаутинг/трансферы, тактическая доска, опросы, интеграции с GPS/видео.
Его сила — процессы внутри клуба, слабость — он не видит лигу целиком. Наши уникальные данные —
разобранные события всех команд региона — дают то, чего у него нет: любой игрок и команда
относительно всей лиги. Поэтому кабинет холдинга строится вокруг решений относительно лиги,
а не вокруг учёта.

Что имеет смысл добавить следующими шагами (по убыванию ценности):
1. **Динамика по неделям** — снимок решений раз в неделю и «что изменилось»: кто вошёл/вышел из
   кандидатов, где просела линия, кто вырос (у федерации уже есть механизм снимков когорт).
2. **Карточка кандидата для решения** — одна страница на игрока с выводом словами («готов в
   молодёжку: топ-6% региона, стабилен 7 матчей, сильнее амплуа лиги по перехватам и передачам»)
   и печатью в PDF для тренерского совета.
3. **Сравнение двух игроков** (наш и кандидат селекции, или два кандидата в молодёжку) по
   36 показателям бок о бок.
4. **Разбор соперника перед матчем** — сильные линии и лучшие игроки соперника по тем же данным,
   что и наши (данные уже в кэше когорты).
5. **Заметки и решения** — руководитель помечает игрока («в молодёжку с января», «наблюдаем»),
   кабинет напоминает и показывает, как изменился рейтинг после решения.
6. **Скаут-лист без имён → с именами по запросу** — экспорт списка селекции в базу разборов,
   где имена доступны по договорённости.
Не повторять: учёт тренировок, медицина, финансы — это другой продукт и другие данные.
