# План: Провижн команд клуба + видимость (open/close)

> Стартовая кодовая фраза для реализации: **«Поехали»**.
> Контекст собран в сессии 2026-06-01 (после фикса парсеров PDF/CSV). Ничего из
> этого ещё НЕ реализовано — это спецификация к исполнению.

## Проблема
- Клуб (tenant) может иметь до 11 команд разных возрастов. Схема это уже
  поддерживает (`teams.tenant_id`, `GET /data/teams` отдаёт все). НО:
  - `POST /admin/tenants` создаёт клуб **без единой команды**.
  - **Нет admin-API создания команд** (`AddTeamSheet` — только переключатель
    существующих, не создатель). Команды заводятся вручную скриптом на клуб → не
    масштабируется.
- Не все клубы покупают все возрасты. Нельзя, чтобы у клуба висели 7 пустых
  команд, когда куплена одна. Нужен механизм **скрытия/открытия** команд по мере
  появления разборов.

## Решение (объединяем «движок» + «UI» + «видимость»)

### Модель данных — БЕЗ изменений схемы
- `teams.active` (boolean, уже есть) = флаг видимости для клубных пользователей.
  `GET /data/teams ... WHERE active = TRUE` уже фильтрует.
- Провиженные команды создаются с `active = FALSE` (скрыты).
- «Открыть команду» = `active = TRUE`; «скрыть» = `FALSE`.
- Решение: переиспользуем `active` как единый флаг «открыта/видна клубу». Если
  позже понадобится отличать soft-delete от «ещё не куплена» — добавить
  `teams.meta.status: 'provisioned' | 'open' | 'archived'` (пока не нужно, KISS).

### Backend
1. **`POST /admin/tenants/:slug/provision-teams`** — читает
   `provider_config.tournaments`, апсертит команду на каждый возраст:
   `id = {slug}-{age}`, `name = "{displayName} {age}"`, `age_group = age`,
   `year = age`, **`active = false`** по умолчанию. Идемпотентно
   (`ON CONFLICT (id) DO NOTHING` — не сбрасывать `active` у уже открытых).
   Возвращает `{created:[], existing:[]}`.
2. **`POST /admin/tenants/:slug/teams`** — ручное создание команды (name + age,
   без турнира) для краевых случаев. `active=false` по умолчанию.
3. **`PATCH /admin/tenants/:slug/teams/:teamId`** — `{ active?, name?, ageLabel? }`
   → открыть/закрыть/переименовать. Через `withBypassRLS` + `authorize('platform_admin')`.
4. **`GET /admin/tenants/:slug/teams`** — список ВСЕХ команд клуба (вкл. inactive),
   с числом матчей на команду (`LEFT JOIN matches`) → бейдж «есть разборы».
5. **Авто-открытие при первом разборе:** в `upload/routes.ts` после успешной
   вставки матча — `UPDATE teams SET active=TRUE WHERE id=$teamId` (команда с
   данными никогда не остаётся скрытой).
6. (Опц.) Свернуть provision в `POST /admin/tenants`, если в `providerConfig`
   уже есть `tournaments`.

### Frontend (админка)
1. **`AdminTenantNew`** (создание клуба): повторяемая секция возрастов —
   строки `[возраст][leagueId][cupId]` с `[+]/[×]`. На submit: создать tenant с
   `providerConfig.tournaments` → вызвать `provision-teams` → (опц.) старт
   calendar sync.
2. **Страница клуба в админке**: таблица команд (вкл. скрытые) с тумблером
   `active` (открыть/закрыть), бейджем «N разборов / нет данных», кнопкой
   «Добавить команду вручную», edit имени/возраста.
3. **Empty-state** «Команды не созданы» → CTA «Провизионировать из турниров» /
   «Добавить команду».
4. Клиентский `GET /data/teams` уже отдаёт только `active=TRUE` — клубные
   пользователи видят только открытые команды. Проверить TeamContext/селектор.

### Видимость — правила
- Клубные роли (head_coach/team_coach/player/parent) видят только `active=TRUE`.
- Провиженные-но-не-открытые: видны только в админке.
- Авто-открытие при первом загруженном матче.
- Админ может открыть/закрыть вручную в любой момент.

## Зависимость
ID турниров по возрастам для нового клуба (напр. «Выборжанин») вводятся вручную
в форму создания (как в `fixMatcher` для Легируса). Вторая итерация (позже):
авто-дискавери через API Наградиона/FFSPB (`/teams`, `/tournaments`) по клубу.

## Немедленный сайд-эффект для Легируса
После реализации: `provision-teams` для `legirus` создаст 2010–2016 (скрытыми),
2010 откроется автоматически при первой загрузке матча (или вручную). Это
заменит разовый скрипт `seedLegirusTeam.ts` (его удалить).

## Acceptance criteria
- [ ] Создание клуба с N возрастами → N команд (скрытых) одним действием.
- [ ] Повтор provision идемпотентен (не трогает уже открытые).
- [ ] Клубный пользователь видит только открытые команды.
- [ ] Загрузка матча авто-открывает команду.
- [ ] Админ может открыть/закрыть любую команду; видит «есть/нет разборов».
- [ ] Никакого кода на конкретный клуб — всё из конфига/формы.
- [ ] TypeScript strict, без `any`; code-review без CRITICAL/HIGH.

- `frontend/src/routes/admin/AdminTenantNew.tsx` — форма возрастов.
- `frontend/src/routes/admin/*` — страница управления командами клуба.
