# Миссия «Погнали» — 100 пунктов глазами тренера-аналитика уровня ЛЧ

> **Кодовая фраза для запуска: «Погнали»** (переопределена 2026-06-02; прежняя
> миссия — распознавание карт — выполнена, см. `MAP_PARSING_PLAN.md`).
> Когда пользователь пишет «Погнали» — выполняется ЭТА миссия.

## Что это

Полноценная оценка нашего решения **глазами профессионального футбольного
тренера-аналитика**, оформленная как **100 пунктов**:

- **33 критики** — что сейчас плохо/непрофессионально/вводит в заблуждение
  (неверные метрики, слабая визуализация, отсутствие контекста, UX-провалы
  при разборе матча).
- **33 улучшения** — как довести существующее до профессионального стандарта
  (точность метрик, читаемость, сравнения, нормализация на 90 мин, перцентили).
- **33 «вау»** — фичи для эффекта «вау даже на уровне команд ЛЧ» (продвинутая
  модельная аналитика, нарративные инсайты, интерактив).

**Реализовать ВСЕ 100.** Пользователь смотрит утром.

## Жёсткое ограничение (единственное)

**Довести до конца.** Незавершённая миссия = провал. Никаких «реализовал часть,
остальное предлагаю». Если пункт не реализуем по данным — заменить его на
эквивалентный реализуемый и пометить, но 100 закрытых пунктов обязательны.
Ограничений по времени/объёму/стоимости НЕТ.

## Решения пользователя (зафиксированы 2026-06-02)

1. **Охват — только матч-аналитика.** Экраны: `frontend/src/pages/MatchDetail.jsx`,
   `PlayerDetail.jsx`, `ClubDashboard.tsx` (+ их компоненты/чарты, backend-данные
   под них: `upload/routes.ts`, `data/*`, парсеры агрегатов). НЕ трогать auth,
   биллинг, multi-tenant ядро, публичные экраны, админку.
2. **Деплой — прямо в `main`.** Коммитить осмысленными порциями прямо в main;
   Render/Vercel деплоят. Билд держать зелёным после каждой порции
   (`cd backend && npx tsc --noEmit`, `cd frontend && npm run build`).
3. **Данные — модельные метрики на НАШИХ данных.** Разрешено выводить продвинутую
   аналитику из того, что есть в SportVisor PDF/CSV (per-player attack/defence/
   fitness, radar, splits 1/2 тайм, командные агрегаты, события, тепловые карты):
   xG-модель/калибровка, xT-подобные оценки продвижения, packing-прокси,
   PPDA/прессинг-индексы, перцентили роли, нормализация на 90 мин, индексы формы.
   **Без выдуманных чисел** — каждая метрика прослеживается до реальных полей;
   модельные оценки честно помечать как оценки.

## Рабочий процесс (для ночной сессии)

1. **Сначала аудит как аналитик.** Пройти MatchDetail/PlayerDetail/ClubDashboard
   и стоящие за ними данные. Выписать честные 100 пунктов (33/33/33) в
   `docs/CL_ANALYST_100_RESULTS.md` — нумерованный список с категорией, файлом-
   якорем и кратким «почему».
2. **Реализовывать по порядку**, отмечая статус каждого пункта в том же файле
   (✅/файлы/коммит). Группировать в коммиты по смыслу, пушить в main порциями.
3. **После каждой порции** — зелёный билд (tsc + vite build). Сломанный билд в
   main недопустим (там автодеплой).
4. **Финал** — сводка в `CL_ANALYST_100_RESULTS.md`: 100/100, что сделано,
   где смотреть, какие пункты заменены и почему.

## Контракты проекта (не нарушать)

- Цвета только через CSS vars (`var(--brand-primary)` и т.д.) — хардкод `#hex`
  запрещён (`CLAUDE.md`).
- TypeScript strict, `any` запрещён без обоснования.
- Tenant scoping тотален; данные матча уже приходят scoped — не обходить.
- «Достоверность» — внутренняя метрика, бейдж клиенту не показываем (есть на
  бэкенде). Командные тепловые карты пока скрыты во фронте (флаг в MatchDetail).

## Якоря данных (что реально доступно на игрока/матч)

- `match_players`: ratings {overall,attack,defence,fitness}, radar (детальный
  Performance Index), stats.attack/defence/fitness (десятки полей: shot, goal,
  pass, progressivePass, keyPass, dribble, tackle, interception, recovery, duel,
  aerialDuel, pressing, counterpressing, clearance, blockedShot…), splits (1/2
  тайм), minutes, number, position, maps.heatmap (per-player).
- `matches`: teamSummaryStats, teamAggregates (по секциям: shooting/passes/
  attacks/possession/recoveries/duels/pressing/positioning/setPieces),
  teamAvgRatings, meta.events (хроника), meta.teamMaps.
- Сезонный контекст: множество матчей тенанта (для перцентилей/средних/формы).

## Идеи «вау» (примерный пул, не исчерпывающий)

xG-модель по зонам ударов; xT/ценность продвижения мяча; PPDA и карта прессинга;
packing-прокси из передач в финальную треть/в штрафную; перцентили игрока по
позиции против команды/сезона; «радар роли» с эталоном позиции; индекс формы по
последним N матчам; нарративные авто-инсайты тренерским языком; сравнение
«матч vs сезон vs топ-перцентиль»; разбор по таймам с трендом; momentum-таймлайн
по событиям; модель ожидаемых очков; карта зон владения/потерь.
