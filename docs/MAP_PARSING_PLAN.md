# План: распознавание карт + честная «Достоверность 100%»

> Стартовая кодовая фраза для реализации: **«Погнали»**.
> Контекст собран в сессии 2026-06-02 (после фикса счёта PDF + транзакций upload).
> Цель: «Достоверность» матча должна показывать честные 100% для нормально
> распознанного отчёта — не подделкой, а реальным распознаванием/корректным
> скорингом.

## Проблема
- Бейдж «Достоверность» = взвешенный балл в
  `backend/src/data/dataQuality.ts` → `computeDataQuality()`:
  игроки 50% + команда 35% + доп 15% (формация 5 / карты 5 / события 3 / таймы 2).
- Сейчас на новом формате просаживается до ~95% из-за «Карты не распознаны»
  (командные карты не вытягиваются) и иногда «Нет разбивки по таймам».
- Карты команды кропаются с **жёстко прописанных страниц 12–20**
  (`backend/parsers/crop_all_b64.py`, `TEAM_PAGES`). Per-player карты ищутся по
  англ. заголовку `HEADER_RE = "Player Stats – <name>"`. Оба — под СТАРЫЙ формат.

## Диагностика нового формата (PDF `6724_4487.pdf`, Легирус 2010-2011, 40 стр.)
Скан по страницам (img = всего изображений, portrait = крупных «полевых» карт):

```
p1–p17 : img=0                      ← текстовые страницы, изображений нет
p18,p19: img=1                      ← одиночные картинки
p21    : img=4
p22–24 : img=1
p25    : img=1 portrait=1           ← единственная крупная портретная карта (формация?)
p26    : img=1
p27–p40: img=7 каждая (14 страниц)  ← per-player страницы, 7 мелких карт на игрока
```

Выводы:
1. **Командных «полевых» карт (9 шт.) как крупных портретных изображений в этом
   формате почти нет** — `_team_bbox()` (портрет ≥180×120, h≥1.15·w) их не находит,
   страницы 12–20 пустые. Возможно командные карты тут — векторные/мелкие/иначе
   свёрстаны. Нужно посмотреть глазами (рендер страниц 18–26 в PNG).
2. **Per-player карты ЕСТЬ** (p27–40, по 7 картинок = radar/heatmap/pass-map/…),
   но `HEADER_RE` (англ.) не матчит русский «бегущий» заголовок страницы
   (на КАЖДОЙ странице первая строка = «27.05.2026 Выборжанин 2010-2011 2:1
   Легирус 2010-2011»). → детекция player-страниц по заголовку не срабатывает.

## Подход (комбинируем извлечение + корректный скоринг)
### A. Извлечение карт под новый формат
1. **Диагностический рендер**: дамп страниц 18–26 и одной player-страницы (p27) в
   PNG (`page.to_image()`), глазами понять, где командные карты и как свёрстаны
   per-player блоки (что за 7 изображений, какое из них heatmap).
2. **Командные карты**: вместо фикс-страниц 12–20 — находить страницы карт по
   тексту-якорю секции (Удары/Передачи/Стандарты/Владение/Атаки/Возвраты/Дуэли/
   Прессинг/Позиционирование) ИЛИ по сигнатуре изображений; обобщить `_team_bbox`
   на верстку нового формата (если карты не портретные — смягчить эвристику AR).
3. **Per-player карты**: детектить player-страницы НЕ по англ. `HEADER_RE`, а по
   тому, что на странице 7 изображений + есть строка с именем игрока из ростера;
   матчить игрока по имени из ростера (`match_player_by_name` уже есть). Вытащить
   именно heatmap (нижний правый блок) — уточнить позицию на реальном рендере.
4. **Не сломать старый формат** (англ. 2010 PDF, командные карты на 12–20):
   детекция должна работать для ОБОИХ — добавить, а не заменить.

### B. Честный скоринг достоверности
- Карты/таймы/события — **best-effort визуал**, не «ядро» данных. Решить с
  пользователем (он выбрал «улучшить парсинг», не «всегда 100%»): если формат
  объективно не содержит командных карт, они НЕ должны топить балл.
- Вариант: сделать скоринг **source-aware** — «ядро» (игроки+рейтинги+командные
  агрегаты) даёт 100%, а карты/события/таймы — бонус/информативные бейджи без
  штрафа, ИЛИ учитываются только если формат их в принципе содержит.
- Цель: нормально распознанный матч (как этот: 14/14 с рейтингами, детальные
  действия 14/14, командные рейтинги есть) = **100%**.

## ✅ Реализовано (2026-06-02)
Эмпирическая диагностика на `6724_4487.pdf` уточнила гипотезу плана:
- **Командные карты** в новом формате — портретные изображения 131–196px на
  страницах-дашбордах с сигнатурой `Attack N/5`/`Defence N/4` + заголовок секции
  («Удары», «Передачи», …). Старый `_team_bbox` резал их порогом 180w и смотрел
  на жёсткие стр. 12–20. → `crop_all_b64.py`: `crop_team_maps_by_content()`
  детектит по контенту (метка секции → slug), порог снижен до 100×120w/h, margin
  6pt; legacy-страницы 12–20 оставлены как фоллбэк для старого формата. Результат:
  **8 карт** (Владение без картинки — честно отсутствует) + **14/14 player-heatmap**.
- **Player-карты УЖЕ работали**: разделитель `Player Stats – Имя Фамилия` — это
  en-dash (входит в `HEADER_RE`), heatmap = нижний-правый блок (страница landscape
  842×595). Добавлен content-fallback `match_player_in_line()` на случай форматов
  без англ. метки + пропуск дашборд-страниц по `_section_slug`.
- **Скоринг** (`dataQuality.ts`) → source-aware: ядро = игроки 65% + командные
  рейтинги 20% + командные агрегаты 15% = 100%. Карты/события/таймы/формация/
  teamSummary — best-effort визуал, в балл НЕ входят (бейджи без штрафа). Полный
  матч = честные 100%; деградация ядра даёт честные <100% с понятными warning'ами.
