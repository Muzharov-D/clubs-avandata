# PRD — Технический долг и исправления по итогам критического ревью

## Контекст
Clubs · Avandata — multi-tenant SaaS-платформа для футбольных клубов (clubs.avandata.ru).
Стек: TypeScript + Fastify 5 + Drizzle + Postgres (backend), React 19 + Vite (frontend).
Этот PRD — список задач по итогам критического аудита кода с трёх позиций:
тех-лид/безопасность, футбольный аналитик (корректность данных), UX-дизайнер.

Три заявленных столпа платформы — изоляция тенантов, white-label тематизация и
строгий TypeScript — на практике держатся на дисциплине разработчика, а не на коде.
Данные чинятся на витрине (фронт) вместо источника (парсер/upload), отсюда серия
из 49 «batch»-фиксов. Цель этих задач — устранить первопричины, а не симптомы.

## Приоритет P0 — Безопасность (критично)

### Убрать временный пароль из HTTP-ответа
В backend/src/admin/routes.ts:147 при создании тенанта временный пароль head_coach
возвращается прямо в теле JSON-ответа (с пометкой TODO). Пароль оседает в логах
прокси/Render, в Sentry, в истории браузера. Заменить на одноразовый invite-токен
со ссылкой на установку пароля (или отправку через Resend). Пароль не должен покидать
сервер в открытом виде. Низкая трудоёмкость, высокий риск.

### Восстановить реальную изоляцию тенантов на уровне БД
Миграция backend/drizzle/0004_relax_rls.sql сняла FORCE ROW LEVEL SECURITY со всех
16 tenant-scoped таблиц и полностью с users. Приложение коннектится как owner таблиц,
а owner обходит RLS-политики по умолчанию — значит политики сейчас инертны, изоляция
держится только на ручном WHERE tenant_id в каждом запросе. Одна забытая фильтрация =
утечка данных между клубами. Решение: завести отдельную app-роль БД без BYPASSRLS,
дать ей GRANT на таблицы, вернуть FORCE RLS, переключить пул на эту роль. Добавить
интеграционный тест, доказывающий, что клуб А не видит данные клуба Б.

### Ввести репозиторный слой с обязательным tenant_id
backend/src/data/routes.ts содержит 10+ сырых conn.query() с ручным WHERE tenant_id.
Сырой SQL обходит type-safety Drizzle ровно там, где цена ошибки максимальна.
Создать слой доступа к данным, где tenant_id физически невозможно не передать
(функция-обёртка или репозиторий), и перевести на него существующие запросы.

## Приоритет P0 — Корректность данных (футбол)

### Отдавать матчи с ID команд вместо имён
В backend API матчи возвращаются с именами home/away, а фронт
(frontend/src/pages/MatchesDashboard.jsx:58-68) определяет «мы дома» через подстроку
h.includes(ourNameLower). Это ломается на «Зенит» vs «Зенит-2»/«Зенит U17», а при
несовпадении имени (опечатка из PDF) команда молча считается гостём — goalsFor и
goalsAgainst меняются местами, сезонная разница голов искажается. Backend должен
возвращать homeTeamId/awayTeamId; фронт должен определять сторону по ID, эвристику
includes() удалить.

### Различать «не оценён» и низкий рейтинг 0
Сейчас рейтинг 0 трактуется как «не играл / не оценён» (frontend/src/utils/colors.js:4,
MatchesDashboard.jsx:117, RatingCard, RatingPill). Это прячет честный низкий рейтинг,
если провайдер когда-либо его выставит. Перейти на null для «не оценён», оставив 0..N
валидным диапазоном. Логику исключения из среднего сохранить (она корректна), но
завязать на null, а не на <= 0.

## Приоритет P1 — Тематизация / white-label (UX, бизнес-критично)

### Токенизировать все цвета через CSS-переменные
CLAUDE.md запрещает хардкод цветов, но 33+ файла содержат захардкоженные hex/rgb
(#1FB6FF в ClubDashboard.css, cyan/#07071c в AppHeader.css, RGB-палитра в StatTile.tsx,
фирменные градиенты в AddTeamSheet.css). Из-за этого второй клуб с другим брендом
получит чужие цвета — white-label не работает, платформу нельзя продать другому клубу.
Завести полный набор семантических CSS-переменных (brand, surface, danger, success,
neutral, а также rating-шкалу --rating-excellent..--rating-poor) и заменить все
хардкоды на var(). Шкала рейтинга в colors.js тоже идёт в токены.

## Приоритет P1 — Устранение первопричины batch-фиксов

### Нормализовать данные в одной точке (upload/парсер)
Серия из 49 batch-фиксов (trimAge, фильтр нулей, дедуп по лейблу, подмена логотипа)
лечит симптомы на фронте. Перенести нормализацию (обрезка возрастного суффикса,
дедупликация, имена/ID команд, валидация рейтингов) в единую точку при upload/парсинге,
до записи в БД. Добавить zod-валидацию вывода Python-парсеров
(backend/src/upload/routes.ts) — сейчас JSON.parse(...) as ExcelOutput не проверяется
в рантайме, данные из внешнего PDF попадают в JSONB без валидации.

### Устранить дубли страниц и утилит
ClubDashboard.tsx, ClubPage.jsx, ClubOverview.jsx, ClubLanding.jsx дублируют логику
(normalizeClubName, topN, trimAge). Утилиты num/fmtDate/trimAge переопределены в 5+
файлах. Это источник расхождений и batch-фиксов. Вынести общие утилиты в один модуль,
свести дублирующиеся страницы к одной с переиспользуемыми компонентами.

## Приоритет P2 — Качество и доступность

### Дедуп состава и предупреждение о переполнении в формации
В frontend/src/components/FormationField.jsx дедуп стартового состава идёт по ключу
«номер-фамилия» — два игрока с одной фамилией и потерянным номером схлопнутся в одного.
А при возврате парсером >11 стартующих список молча режется до 11 без предупреждения.
Сделать дедуп устойчивым (по стабильному player.id) и логировать/сигнализировать,
когда данные о составе переполнены или противоречивы.

### Доступность: не кодировать смысл только цветом
Рейтинги и дельты (StatTile accent red/green, hue-шкала рейтинга) различимы только по
цвету — ~8% мужчин-дальтоников не считают смысл. Добавить избыточность: знак/иконку
(стрелка вверх/вниз, символ) и текст. SVG-графики (PlayerRadar.tsx) снабдить role="img"
и aria-label для скринридеров.

### Перевести фронт на mobile-first и убрать фиксированные ширины
Продукт для телефонов тренеров/родителей, но медиа-запросы desktop-first (max-width),
есть фиксированные min-width: 380px (PlayerDetail.css), дающие горизонтальный скролл на
узких экранах. Тач-таргеты бейджей бывают <44px. Перейти на mobile-first брейкпоинты,
убрать фиксированные ширины, проверить тач-таргеты по WCAG.

## Приоритет P2 — Гигиена

### Привести CORS к окружениям
backend/src/server.ts содержит localhost:5173 в production-списке CORS. Убрать dev-origin
из прод-конфигурации, развести origins по окружениям.

### Синхронизировать CLAUDE.md с реальностью
CLAUDE.md заявляет «Phase 0 skeleton» и «строгий TypeScript везде, any запрещён», но
проект — зрелое приложение, а фронт на 90%+ нетипизированных .jsx. Обновить документ:
актуальный статус фаз, реальное состояние типизации, план миграции .jsx -> .tsx.
